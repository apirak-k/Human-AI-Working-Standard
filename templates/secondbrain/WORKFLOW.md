# HAWS Default Engineering Workflow

This generic starter describes a six-phase workflow. It does not select a
particular AI, repository, tool, or skill. Use whichever available capabilities
are relevant to the current task, and let a personal DEV overlay refine this
workflow when one is present.

## Six Phases

1. **Discover** — confirm the goal, current state, constraints, and non-goals.
2. **Design** — compare viable approaches and choose the smallest safe boundary.
3. **Plan** — break the work into ordered, testable slices with checkpoints.
4. **Implement** — make one bounded change at a time and preserve unrelated work.
5. **Verify** — run the relevant checks, inspect results, and label unknowns.
6. **Handoff** — update the current documentation, record the checkpoint, and
   state the next action clearly.

## Operating Rules

- Keep the human's latest intent as the highest project-level priority.
- Prefer reversible, minimal changes and explicit ownership boundaries.
- Use evidence before completion claims; distinguish automated verification from
  human acceptance.
- Select tools and skills dynamically; this file intentionally contains no fixed
  skill list.
